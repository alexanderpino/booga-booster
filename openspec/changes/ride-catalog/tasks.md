# Tasks

Conventions for every group: write the failing test first and name the rule in the test name; any C# task starts with "consult the `4dotnet-csharp-style-guide` MCP server first" (once per group, again when the folder layout changes); features under `Features/<Feature>/` with a command or query plus a handler using `ExecuteAsync`; endpoints contain no business logic; DTOs under `<Module>.Abstractions/DataTransferObjects/<Feature>/`; properties, never public fields; no magic numbers (constants in the module's tuning or constants class, derivations in `docs/park/02-ride-catalog.md`); determinism: fixed 1/120 s step, injected sampler, `TimeProvider`; tests with xUnit v3 + Moq + Bogus, no FluentAssertions, at least 80 percent line coverage on module libraries; Angular 22 zoneless, signals, OnPush, PrimeNG for new UI (consult the `primeng` MCP server first), Vitest + axe-core. Backend tests: `src/Tests/FourDotnet.BoogaBooster.Catalog.Tests` and `src/Tests/FourDotnet.BoogaBooster.Controller.Tests`.
