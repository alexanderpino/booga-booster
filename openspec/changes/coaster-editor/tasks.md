Conventions for every task below. C# work starts by consulting the `4dotnet-csharp-style-guide` MCP server (`search_documents` for the topic of the task) and follows it. Data members are properties, never public fields. Every behaviour task is test-first: write the failing xUnit v3 test named after the rule, see it fail, implement, see it pass. No FluentAssertions. No magic numbers: constants live in `Coaster/Domain/CoasterParameters.cs`, derivations in `docs/coaster/`. Randomness in tests is a seeded `Random`, and failure messages print the seed. Backend paths are relative to `src/`; the test project is `Tests/FourDotnet.BoogaBooster.Coaster.Tests` ("tests"). Client paths are relative to `src/FourDotnet.BoogaBooster.App/src/app/coaster/` ("client"); client tests are Vitest, with axe-core for accessibility. Run `dotnet test Tests/FourDotnet.BoogaBooster.Coaster.Tests` from `src/` after every backend group and `npx vitest run coaster` from the app folder after every client group. Tier tags: **Tier 1** is the MVP (groups 1 to 11) and ends with a checkpoint; **Tier 2** (groups 12 to 15) and **Tier 3** (group 16) are independent of each other and may be skipped; group 17 closes whichever slice was built.

**Stop line:** after group 11 the change is demo-ready (see the demo script in design D20). To stop there, skip to group 17.
