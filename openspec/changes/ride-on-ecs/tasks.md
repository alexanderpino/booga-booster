# Tasks

Conventions for every group.

- **Strangler-fig rule.** Each numbered group ends in one or more logical Conventional Commits, and **every commit builds and passes `dotnet test src/Tests/FourDotnet.BoogaBooster.DigitalTwin.Tests` from `src/`**. The default engine stays `Legacy` until task 14.1, and `Ecs`/`Shadow` are rejected at start-up with "not yet supported" until task 7.4, so an unfinished engine is never reachable by configuration. If a task would leave the build red, split it; do not commit red.
- Backend code lives in `src/DigitalTwin/FourDotnet.BoogaBooster.DigitalTwin/` (ECS code under `Ecs/Components`, `Ecs/Systems`, `Ecs/Acl`, `Ecs/Observability`) and `src/DigitalTwin/FourDotnet.BoogaBooster.DigitalTwin.Abstractions/`; tests in `src/Tests/FourDotnet.BoogaBooster.DigitalTwin.Tests/` (subfolders `Ecs/`, `Equivalence/`, `Contracts/`). Frontend under `src/FourDotnet.BoogaBooster.App/`.
- xUnit v3, Moq, Bogus, `Assert`; no FluentAssertions. Properties, never public fields. No magic numbers: constants live in `Domain/RideParameters.cs` or a named constants class next to the code, with the rationale in `docs/`.
- Each group lands its own tests and docs. Test first, then code.
- Before writing any C#, consult the `4dotnet-csharp-style-guide` MCP server (task 1.3). Before using any PrimeNG component, consult the `primeng` MCP server.
- Run the full backend suite only in groups 14 and 15; elsewhere scope to the DigitalTwin test project.
